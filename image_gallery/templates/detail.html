Structure follows docs/ui/design-system.md § Detail view. It carries no image data. The script fetches `/api/images/` and fills this in from the payload (docs/adr/0022-the-detail-page-joins-the-client.md), which is how the gallery has always worked — the two pages now share one model. The **controls are server-rendered**, the **values are not**. That is the same split index.html uses: F2.5 wants a real control in the document, one that survives a scripting failure and is visible to a reader of the HTML, while the values it displays are resolved server-side and only known after the fetch. The notice banner is deliberately absent. A scenario asserts the element is *missing* when there is nothing to say, not merely empty, so the client creates it only when the payload carries one. `data-testid` attributes are the contract the browser suite binds to — see tests/e2e/test_detail_steps.py. They are never styling classes. {% endcomment %} {% block content %} ← Back to gallery {% comment %} `data-image-id` is what the script reads to know which image to ask about — the id is in the path, so the server knows it before any script runs and the client never has to parse a URL. `data-api-url-template` is reversed here for the same reason the gallery reverses its own: no path is written in JavaScript (F5.4). {% endcomment %}
